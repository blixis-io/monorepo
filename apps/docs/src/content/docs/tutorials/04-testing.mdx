Blixis tests run your module the way production does: real Postgres, real migrations, and real request scopes. Only the event transport is swapped for an in-process one, so you can assert on events and deliver them when you choose.

## Set up

```bash
docker compose up -d postgres   # Postgres 18 on localhost:5432
pnpm test:db                    # runs tests with BLIXIS_TEST_DATABASE_URL set
```

Without the database, `pnpm test` skips database tests; CI always runs them.

## The test

```ts title="test/notes.test.ts"
import { databaseModule } from '@blixis/database'
import { idempotencyModule } from '@blixis/database/idempotency'
import { eventsModule } from '@blixis/events'
import { outboxModule } from '@blixis/events/outbox'
import { newId } from '@blixis/shared'
import { captureEvents, createTestBlixis } from '@blixis/testing'
import { createTestDatabase, databaseTestsEnabled, type TestDatabase } from '@blixis/testing/database'
import { sql } from 'drizzle-orm'
import { afterAll, beforeAll, beforeEach, describe, expect, it } from 'vitest'
import { notesModule } from '../src/index.ts'

describe.skipIf(!databaseTestsEnabled())('notes module', () => {
  const modules = () => [databaseModule(), outboxModule(), idempotencyModule(), notesModule()]
  let db: TestDatabase
  beforeAll(async () => {
    db = await createTestDatabase({ modules: [...modules(), eventsModule()] })  // fresh, migrated DB
  })
  beforeEach(() => db.reset())       // empty all module tables between tests
  afterAll(() => db.drop())

  async function setup() {
    const events = captureEvents({ mode: 'deferred' })   // deliver on flush(), like "after commit"
    const t = await createTestBlixis({ modules: [...modules(), events.module()], database: db })
    return { t, events }
  }
  const space = newId()

  it('creates a note and reads it back, scoped to its space', async () => {
    const { t } = await setup()
    const created = await t.request(`/api/v1/spaces/${space}/notes`, {
      method: 'POST',
      json: { title: 'Hello', body: 'First note' },
    })
    expect(created.status).toBe(201)
    const note = (await created.json()) as { id: string; title: string }

    expect((await t.request(`/api/v1/spaces/${space}/notes/${note.id}`)).status).toBe(200)
    expect((await t.request(`/api/v1/spaces/${newId()}/notes/${note.id}`)).status).toBe(404)
  })

  it('rejects invalid input with 400', async () => {
    const { t } = await setup()
    const res = await t.request(`/api/v1/spaces/${space}/notes`, { method: 'POST', json: { title: '' } })
    expect(res.status).toBe(400)
  })

  it('emits note.created after commit and counts notes exactly once', async () => {
    const { t, events } = await setup()
    await t.request(`/api/v1/spaces/${space}/notes`, { method: 'POST', json: { title: 'Counted' } })
    events.expectEvent('note.created', (e) => (e.payload as { title: string }).title === 'Counted')

    await events.flush()
    await events.flush()   // flushing again delivers nothing new
    const counts = await db.db.execute(sql`select count from notes.note_counts where space_id = ${space}::uuid`)
    expect(counts.rows).toEqual([{ count: 1 }])
  })

  it('replays a retried create instead of creating a second note', async () => {
    const { t, events } = await setup()
    const create = () =>
      t.request(`/api/v1/spaces/${space}/notes`, {
        method: 'POST',
        json: { title: 'Once' },
        headers: { 'idempotency-key': 'create-once' },
      })
    const first = await create()
    const retry = await create()
    expect(retry.headers.get('idempotent-replayed')).toBe('true')
    expect(await retry.json()).toEqual(await first.json())
    expect(events.emitted).toHaveLength(1)
  })
})
```

## What each piece does

| Piece | Purpose |
|---|---|
| `createTestDatabase({ modules })` | A fresh database for this file, migrated with the production runner. Parallel test files never share one |
| `db.reset()` | Truncates module tables between tests, keeping the migrations |
| `createTestBlixis({ modules, database })` | Boots the app with `DATABASE` pointing at the test database, and sends requests with `t.request` |
| `captureEvents({ mode: 'deferred' })` | Records every event (`expectEvent`, `emitted`), and delivers it to subscribers through the production dispatch path when you call `flush()` |

<Aside type="note">
`captureEvents` in `deferred` mode mirrors production: handlers run after the request's transaction has committed. In `immediate` mode, handlers run during `emit`, before commit. That's useful for best-effort events, but misleading for transactional ones.
</Aside>
