Modules announce what happened with **events** and react to other modules' events with **subscriptions**. Domain code publishes through the event bus — never directly to Cloudflare Queues.

## Defining an event

```ts
import { defineEvent } from '@blixis/contracts'
import { z } from 'zod'

export const entryPublished = defineEvent({
  type: 'entry.published',
  version: 1,
  delivery: 'transactional',
  description: 'An entry version was published.',
  schema: z.object({ entryId: z.string(), spaceId: z.string(), versionId: z.string() }),
})
```

- **Name:** `<aggregate>.<past-tense-verb>`, lowercase; sub-aggregates allowed (`webhook.delivery.failed`).
- **Payload:** small and JSON-serialisable — IDs, not whole documents. The payload type is inferred from the schema.
- **Version:** starts at `1`; bump it for incompatible payload changes.

## Delivery classes

| `delivery` | Guarantee | Use when |
|---|---|---|
| `transactional` | Written in the same database transaction as your change; delivered at least once if the transaction commits, never if it rolls back. Needs `options.transaction` when emitting. | Losing the event would leave the system wrong (cache invalidation, webhooks). |
| `best-effort` | Sent after the operation; may be lost. | Pure side effects (analytics). |

## Emitting

Resolve the bus from your request's services. It's provided by the `eventsModule()` platform module from `@blixis/events`:

```ts
import { EVENT_BUS } from '@blixis/contracts'
import { toTransactionScope, withTransaction } from '@blixis/database'

await withTransaction(db, async (tx) => {
  const [version] = await tx.insert(entryVersions).values(input).returning()
  await ctx.services.get(EVENT_BUS).emit(
    entryPublished,
    { entryId, spaceId, versionId: version.id },
    { transaction: toTransactionScope(tx) },   // required for transactional events
  )
})
```

The payload is type-checked against the schema at compile time and validated at runtime. It must be plain JSON: no `Date`, `Map`, class instances, `undefined`, or `NaN`, so use ISO strings for times. The bus fills in the [`EventEnvelope`](/api/contracts/interfaces/eventenvelope/):
- `id` (UUIDv7) and `timestamp`;
- the tenant IDs of the current request;
- tracing `metadata`: correlation ID and actor.

Emitting a transactional event without `{ transaction }` fails immediately. Two modules that define the same event type and version differently fail at startup, so import the same `defineEvent` result everywhere.

## Handling

```ts
import { subscribe } from '@blixis/contracts'

export const invalidateCache = subscribe(entryPublished, 'invalidate-delivery-cache', async (envelope, ctx) => {
  ctx.logger.info('invalidating', { entryId: envelope.payload.entryId, attempt: ctx.attempt })
})
// module: events: [invalidateCache]
```

<Aside type="caution" title="Handlers must be idempotent">
Events are delivered **at least once**. A retry or redelivery must not repeat side effects. The subscription `id` is the key for processed-event records — never rename it casually.
</Aside>

- [`EventHandlerContext`](/api/contracts/interfaces/eventhandlercontext/) gives you `attempt`, `logger`, and request-scoped `services`.
- Subscription `id`s must be unique within your module; duplicates fail startup.
- Pass `{ versions: [1, 2] }` to `subscribe` when a handler accepts several payload versions.
