Services throw **public errors** from `@blixis/contracts`. Each has a stable `code`; REST and GraphQL translate the code into their protocol. Never throw HTTP- or GraphQL-specific errors from a service.

## Error classes

| Class | `code` | Shown to clients | REST | GraphQL `extensions.code` |
|---|---|---|---|---|
| [`ValidationError`](/api/contracts/classes/validationerror/) | `VALIDATION_FAILED` | yes, with `details.issues` | 400 | `VALIDATION_FAILED` |
| [`NotFoundError`](/api/contracts/classes/notfounderror/) | `NOT_FOUND` | yes | 404 | `NOT_FOUND` |
| [`ConflictError`](/api/contracts/classes/conflicterror/) | `CONFLICT` | yes | 409 | `CONFLICT` |
| [`ForbiddenError`](/api/contracts/classes/forbiddenerror/) | `FORBIDDEN` | yes | 403 | `FORBIDDEN` |
| [`UnauthorizedError`](/api/contracts/classes/unauthorizederror/) | `UNAUTHORIZED` | yes | 401 | `UNAUTHORIZED` |
| [`RateLimitError`](/api/contracts/classes/ratelimiterror/) | `RATE_LIMITED` | yes, plus `Retry-After` | 429 | `RATE_LIMITED` |
| [`ModuleError`](/api/contracts/classes/moduleerror/) | `MODULE_ERROR` | **no** | 500 | `INTERNAL` |
| [`InfrastructureError`](/api/contracts/classes/infrastructureerror/) | `INFRASTRUCTURE_ERROR` | **no** | 503 if `retryable`, else 500 | `INFRASTRUCTURE_ERROR` |
| anything else | `INTERNAL` | **no** | 500 | `INTERNAL` |

## What clients receive (REST)

Every error response uses [RFC 9457 problem details](https://www.rfc-editor.org/rfc/rfc9457) with content type `application/problem+json`:

```json
{
  "type": "urn:blixis:problem:VALIDATION_FAILED",
  "title": "Validation failed",
  "status": 400,
  "code": "VALIDATION_FAILED",
  "detail": "Invalid entry",
  "requestId": "0192f0c8-8a4e-7b1a-9c3d-4e5f6a7b8c9d",
  "errors": [{ "path": ["title"], "message": "Required" }]
}
```

- `code` is the stable, machine-readable value — branch on it, not on `title` or `detail`.
- `requestId` matches the `x-request-id` response header; include it in bug reports.
- `RateLimitError` adds a `Retry-After` header.
- Server errors (500/503) always carry a generic `detail`. The real cause goes only to the logs and to the app's [`ErrorReporter`](/api/kernel/interfaces/errorreporter/) (Sentry in the API Worker). The report is tagged with request id, correlation id, route, actor type, space, and module. 4xx errors are never reported.

## Throwing

```ts
import { ConflictError, NotFoundError, ValidationError } from '@blixis/contracts'

throw new NotFoundError('Entry not found')
throw new ConflictError('Slug is already taken', { details: { field: 'slug' } })
throw new ValidationError('Invalid entry', [{ path: ['title'], message: 'Required' }])
```

- `details` must be JSON-serialisable and safe to show.
- Wrap database, network, or storage failures in `InfrastructureError` with `cause`; set `retryable: true` when a retry may succeed.
- `ModuleError` is for broken configuration or contract violations; its message starts with the module name.

## Checking and exposing

- [`isBlixisError(value)`](/api/contracts/functions/isblixiserror/) checks a brand instead of `instanceof`, so it works across duplicated package copies.
- [`toPublicErrorShape(error)`](/api/contracts/functions/topublicerrorshape/) returns `{ code, message, details? }` for clients. Non-exposed and unknown errors get a generic message; stack traces and causes are never included.

<Aside type="tip">
Return `NotFoundError` (not `ForbiddenError`) when a caller asks for a resource in a tenant they are not a member of. That avoids revealing which IDs exist.
</Aside>
