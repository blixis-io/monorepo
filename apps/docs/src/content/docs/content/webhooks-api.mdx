A **webhook** sends an HTTPS `POST` to your endpoint when something happens in a space: an entry is published, an asset is deleted, and so on. Use it to rebuild a static site, purge a CDN, or sync a search index. Deliveries are signed, retried, and logged.

Paths are relative to `/api/v1`. Webhooks send data out of Blixis, so only **admins** have `webhooks.read` and `webhooks.manage` by default.

| Method | Path | Permission |
|---|---|---|
| `GET` | `/spaces/:spaceId/webhooks` | `webhooks.read` |
| `POST` | `/spaces/:spaceId/webhooks` | `webhooks.manage` |
| `GET` | `/webhooks/:webhookId` | `webhooks.read` |
| `PATCH` | `/webhooks/:webhookId` | `webhooks.manage` (needs `If-Match`) |
| `POST` | `/webhooks/:webhookId/rotate-secret` | `webhooks.manage` |
| `DELETE` | `/webhooks/:webhookId` | `webhooks.manage` |
| `GET` | `/webhooks/:webhookId/deliveries` | `webhooks.read` |
| `GET` | `/webhooks/:webhookId/deliveries/:deliveryId` | `webhooks.read` |
| `POST` | `/webhooks/:webhookId/deliveries/:deliveryId/redeliver` | `webhooks.manage` |
| `POST` | `/webhooks/:webhookId/test` | `webhooks.manage` |

## Create a webhook

```http
POST /api/v1/spaces/{spaceId}/webhooks
Content-Type: application/json

{
  "name": "Rebuild the site",
  "url": "https://ci.example.com/hooks/blixis",
  "eventTypes": ["entry.published", "entry.unpublished", "asset.*"]
}
```

Answers `201`:

```json
{
  "webhook": {
    "id": "01a0e2…",
    "name": "Rebuild the site",
    "url": "https://ci.example.com/hooks/blixis",
    "eventTypes": ["entry.published", "entry.unpublished", "asset.*"],
    "environmentId": null,
    "active": true,
    "secretHint": "whsec_…Xk2Q",
    "failureCount": 0,
    "disabledReason": null,
    "version": 1,
    "createdAt": "…", "updatedAt": "…", "createdBy": "user:…", "updatedBy": "user:…"
  },
  "secret": "whsec_4Yb…Xk2Q"
}
```

<Aside type="caution">
The **`secret` is returned only here** (and when you rotate it). Store it in your receiver's configuration: it verifies that deliveries come from Blixis. Later reads show `secretHint` only. Blixis stores the secret encrypted.
</Aside>

| Property | |
|---|---|
| `name` | 1–100 characters |
| `url` | the endpoint (rules below) |
| `eventTypes` | 1–50 of the event types below, a group such as `entry.*`, or `*` for all |
| `environmentId` | optional: only events of this environment; omit or `null` for every environment of the space |
| `active` | default `true`; inactive webhooks receive nothing |

## Event types

| Group | Types |
|---|---|
| entries | `entry.created`, `entry.updated`, `entry.published`, `entry.unpublished`, `entry.deleted` |
| content model | `content-type.created`, `content-type.updated`, `content-type.deleted` |
| assets | `asset.created`, `asset.updated`, `asset.published`, `asset.unpublished`, `asset.deleted` |

Other events (users, memberships, sign-ins) are never sent to webhooks.

## What your endpoint receives

A JSON `POST` per event and webhook:

```json
{
  "id": "01a0e3c1-…",
  "type": "entry.published",
  "version": 1,
  "createdAt": "2026-09-27T10:00:00.000Z",
  "spaceId": "01a0da7b-…",
  "environmentId": "01a0da7b-…",
  "data": { "entryId": "…", "contentTypeId": "…", "versionId": "…" }
}
```

- **`data` holds ids only:** fetch the content itself through the [Delivery API](/content/delivery-api/). Entries send `entryId`, `contentTypeId`, `versionId`; content types `contentTypeId`, `apiId`, `kind`, `version`; assets `assetId`, `version`.
- **At least once:** the same event may arrive more than once. Deduplicate on `id`.
- **Ignore unknown fields:** new optional fields may be added; incompatible changes get a new `version`.

## Verify requests

Every request carries `Blixis-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256 of "<t>.<raw body>">`, signed with the webhook's secret, and `Blixis-Delivery-Id`, `Blixis-Event-Id`, `Blixis-Event-Type`. Verify the signature on the **raw** body and reject timestamps older than a few minutes. A complete, tested example (Web Crypto: Node, Workers, Deno, Bun) is in [the receiver contract](https://github.com/blixis-io/monorepo/blob/main/docs/api/webhooks.md#verify-the-signature); `@blixis/webhooks` exports the same check as [`verifyWebhookSignature`](/api/webhooks/functions/verifywebhooksignature/).

## Retries and failures

- Answer **2xx within 10 seconds**; queue slow work.
- **408, 429, 5xx, redirects, timeouts, network errors** are retried after about 1 min, 5 min, 15 min, 1 h, 3 h, 6 h and 12 h (8 attempts, ~22 hours).
- **Other 4xx** answers stop retries for that delivery.
- After **50 consecutive failed attempts**, Blixis disables the webhook (`active: false`, `disabledReason`). Reactivate it with `PATCH { "active": true }` once the endpoint works.

## Delivery log

Every event sent to a webhook is a **delivery**; every HTTP try is an **attempt**.

- **`GET /webhooks/:id/deliveries`** lists deliveries newest first: `{ deliveries, nextCursor }`. Filter with `?status=pending|succeeded|failed|abandoned`; page with `limit` (1–100, default 25) and `cursor`.
- **`GET /webhooks/:id/deliveries/:deliveryId`** adds `attemptLog`: each attempt's number, start, duration, status code, error, and the first 1 KB of your response. Request headers and secrets are never logged.
- **Retention:** finished deliveries are kept for **30 days**; pending ones until they finish.

```json
{
  "id": "01a0e3c2-…",
  "eventId": "01a0e3c1-…",
  "eventType": "entry.published",
  "status": "succeeded",
  "attempts": 2,
  "nextAttemptAt": null,
  "lastStatusCode": 200,
  "lastError": null,
  "payload": { "id": "01a0e3c1-…", "type": "entry.published", "…": "…" },
  "createdAt": "…",
  "updatedAt": "…"
}
```

## Redeliver and test

- **`POST /webhooks/:id/deliveries/:deliveryId/redeliver`** answers `202` and sends the delivery again right away, with the same `Blixis-Delivery-Id` and event id, so your deduplication still works. It adds one attempt, also to a delivery that gave up. Send an `Idempotency-Key` to make retries of the request safe.
- **`POST /webhooks/:id/test`** answers `202` and sends a signed **`webhook.ping`** to the endpoint through the normal delivery path (`data: { "webhookId": "…" }`). Use it to check your endpoint and signature verification. Inactive webhooks answer `409`.

## URL rules

Blixis fetches webhook URLs from its own servers, so it refuses URLs that could reach internal systems:

- **`https://` only.** Local development also accepts `http://localhost` receivers.
- **Public hosts only:** no `localhost`, `*.local`, `*.internal`, single-label names, or metadata hosts.
- **Public addresses only:** no private, loopback, link-local, carrier-grade NAT, or documentation IP ranges, in any notation (`127.1`, `0x7f.1`, `[::ffff:10.0.0.1]` …).
- **No credentials in the URL**, at most 2048 characters.

The rules are checked when you save a webhook and again before every delivery.

## Change, rotate, delete

- **`PATCH /webhooks/:id`** with `If-Match: "<version>"` (or `expectedVersion`) changes `name`, `url`, `eventTypes`, `environmentId`, or `active`. Omitted properties stay.
- **Reactivating** a webhook that Blixis disabled after repeated failures (`active: true`) clears `failureCount` and `disabledReason`.
- **`POST /webhooks/:id/rotate-secret`** returns a new `secret` once; deliveries are signed with it from then on.
- **`DELETE /webhooks/:id`** removes the webhook and its delivery log. Deleting a space removes its webhooks.
