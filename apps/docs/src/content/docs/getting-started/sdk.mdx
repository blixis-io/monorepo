`@blixis/sdk` is the typed client for the Blixis APIs. It has **no dependencies** and runs wherever `fetch` does: Cloudflare Workers, browsers, Node 20+, Deno, Bun, and frameworks such as Astro. Its types are generated from the [OpenAPI document](/concepts/api-reference/), so they always match the API.

## Connect

```ts
import { createBlixisClient } from '@blixis/sdk'

const blixis = createBlixisClient({
  baseUrl: 'https://api.example.com',
  token: process.env.BLIXIS_TOKEN, // an API token (blx_pat_…) from POST /api/v1/auth/tokens
})
```

| Option | Default | |
|---|---|---|
| `baseUrl` | — | the API's origin |
| `token` | — | an API token or an access token, or a function returning one (asked before every request) |
| `timeoutMs` | 30 000 | per attempt |
| `retries` | 2 | for `429`, `502`–`504`, and network errors, on requests that are safe to repeat |
| `fetch` | global `fetch` | replace for tests or instrumentation |
| `credentials` | fetch's default | `include` sends cookies cross-origin |
| `onUnauthorized` | — | called on a `401`; resolve `true` after renewing the token to repeat the request once |

For scripts, `signIn({ baseUrl }, { email, password })` returns a session whose `accessToken` works as `token` (15 minutes).

### Sign in from a browser app

First-party browser apps, such as the admin, use `createBrowserSession`. The access token stays in memory; the refresh token is an `HttpOnly; SameSite=Strict` cookie that scripts can't read. The session renews the access token before it expires and after a `401`, one refresh at a time (across tabs too, with the Web Locks API).

```ts
import { createBrowserSession } from '@blixis/sdk'

const session = createBrowserSession({ baseUrl: 'https://api.example.com' })
if ((await session.restore()) === null) await session.signIn({ email, password })
const organizations = await session.client.organizations.list()
session.subscribe((user) => {
  if (user === null) showSignIn() // signed out, or the session expired
})
await session.signOut()
```

The page's origin must be listed in the API's `AUTH_ALLOWED_ORIGINS` (CORS and the cookie endpoints) and be on the same site as the API, e.g. `admin.example.com` beside `api.example.com`. Never put tokens in `localStorage`.

<Aside type="caution">
Keep management tokens on the server. Never ship them to browsers; websites read content with delivery keys through GraphQL.
</Aside>

## Manage content

```ts
const page = await blixis.contentTypes.create(spaceId, {
  apiId: 'page',
  name: 'Page',
  fields: [{ apiId: 'title', name: 'Title', type: 'text', required: true }],
})

const draft = await blixis.entries.create(spaceId, 'page', { title: 'Home' })
const saved = await blixis.entries.update(draft.sys.id, { title: 'Welcome' }, draft.sys.version)
await blixis.entries.publish(saved.sys.id)

// Every entry, fetching pages as you go
for await (const entry of blixis.entries.iterate(spaceId, { contentType: 'page' })) {
  console.log(entry.fields.title)
}
```

- **Versions:** `update` takes the version you edited; if someone saved in between, it throws a `409` (`CONFLICT`). Reload and retry.
- **Commands are safe to retry:** `publish`, `unpublish`, and redeliveries send an `Idempotency-Key` automatically, the same on every retry. Pass `{ idempotencyKey }` to deduplicate across processes.

## Upload files

```ts
const asset = await blixis.assets.upload(spaceId, file, { filename: file.name }) // up to 90 MiB
await blixis.assets.publish(asset.sys.id)

// Large files: in parts, with progress
await blixis.assets.uploadLarge(spaceId, bigFile, {
  filename: bigFile.name,
  onProgress: (sent, total) => console.log(`${Math.round((sent / total) * 100)}%`),
})
```

Pass `contentType` when the body isn't a `Blob` with a type, `sha256` (hex) to have the server verify the bytes, and `size` for streams.

## Everything else

The resources cover the common flows: `organizations`, `spaces`, `contentTypes`, `entries`, `assets`, `webhooks`, `deliveryKeys`, `apiTokens`. **Every** operation is also available by its `operationId`, fully typed:

```ts
const { locales } = await blixis.call('listLocales', { params: { spaceId } })
await blixis.call('createLocale', { params: { spaceId }, body: { code: 'nl-NL', fallbackCode: 'en-US' } })
```

The operation ids are in the [OpenAPI document](/concepts/api-reference/) (`GET /api/v1/openapi.json`).

## Read content (GraphQL)

Websites read published content through the [Delivery API](/content/delivery-api/) with a **delivery key**:

```ts
import { createBlixisGraphQLClient } from '@blixis/sdk'

const delivery = createBlixisGraphQLClient({
  baseUrl: 'https://api.example.com',
  token: env.BLIXIS_DELIVERY_KEY, // blx_dk_…
})

const data = await delivery.query(
  /* GraphQL */ `query Pages($locale: Locale, $preview: Boolean) {
    pageCollection(locale: $locale, preview: $preview) { items { title slug } }
  }`,
  {},
  { locale: 'nl-NL' },
)
```

- **`locale` and `preview`** are passed as the `$locale` and `$preview` variables: declare them in your query to use the options.
- **Preview** (`preview: true`) needs a **preview key** (`blx_pk_…`). Use it only on the server — never ship it to browsers.
- **Persisted queries** are on by default: the SDK sends the query's SHA-256 as a short GET, which the [delivery cache](/content/delivery-api/#caching) and CDNs can serve; the full query is sent once, when the server doesn't know it yet. Turn them off with `persistedQueries: false`, and GET with `get: false`.
- **Errors** in a GraphQL response throw `BlixisApiError` with the first error's `extensions.code` (`FORBIDDEN`, `VALIDATION_FAILED`, …); all errors and any partial `data` are in `error.details`.

### Typed queries with GraphQL Codegen

The delivery schema is typed per content model, so generate types for your queries from your own space with [GraphQL Codegen](https://the-guild.dev/graphql/codegen)'s client preset in **string mode**. The SDK accepts its documents and infers result and variable types:

```ts
// codegen.ts
import type { CodegenConfig } from '@graphql-codegen/cli'

const config: CodegenConfig = {
  schema: {
    'https://api.example.com/graphql': { headers: { authorization: `Bearer ${process.env.BLIXIS_DELIVERY_KEY}` } },
  },
  documents: ['src/**/*.{ts,astro}'],
  generates: { './src/gql/': { preset: 'client', config: { documentMode: 'string' } } },
}
export default config
```

```ts
import { graphql } from './gql'

const Pages = graphql(`query Pages($locale: Locale) { pageCollection(locale: $locale) { items { title } } }`)
const data = await delivery.query(Pages, { locale: 'nl-NL' }) // data.pageCollection.items[0].title: string | null
```

Introspection needs a member token in production; generate against staging or with a member's token.

## Errors

Failed calls throw `BlixisApiError`:

```ts
import { BlixisApiError } from '@blixis/sdk'

try {
  await blixis.entries.publish(entryId)
} catch (error) {
  if (error instanceof BlixisApiError && error.code === 'VALIDATION_FAILED') {
    for (const issue of error.errors) console.log(issue.path.join('.'), issue.message)
  } else throw error
}
```

| Property | |
|---|---|
| `status` | HTTP status; `0` when no answer arrived |
| `code` | `VALIDATION_FAILED`, `NOT_FOUND`, `CONFLICT`, `FORBIDDEN`, `UNAUTHORIZED`, `RATE_LIMITED`, …, or `NETWORK_ERROR` ([errors](/concepts/errors/)) |
| `errors` | validation issues: `path` and `message` |
| `requestId` | the request in the server's logs — include it when you report a problem |
