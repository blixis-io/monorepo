Blixis is a **modular headless CMS** that runs on **Cloudflare Workers**. Everything it does — content, assets, users, permissions, webhooks — is implemented as **modules** that are composed into one API Worker.

## One contract for every module

A module shipped with Blixis (`@blixis/content`) and a module you publish to npm (`@acme/blixis-seo`) implement **the same public contract** from [`@blixis/contracts`](/api/contracts/readme/). Nothing is special-cased. If a feature needs internal imports from another module, the contract is incomplete — and we treat that as a bug.

```text
apps/api (composition root)
  └─ modules: [auth(), users(), spaces(), content(), assets(), seo()]
        │
        ▼
@blixis/kernel ── validates the module graph, registers services,
                  mounts REST routes, composes GraphQL, wires events
        │
        ▼
@blixis/contracts ── the types and helpers every module builds against
```

Modules communicate only through **public contracts**: typed [service tokens](/concepts/services-and-capabilities/), [capabilities](/concepts/services-and-capabilities/#capabilities), and [events](/concepts/events/).

## What you can use today

| Package | Status | What it gives you |
|---|---|---|
| `@blixis/contracts` | ✅ available | Module contract, service tokens, capabilities, errors, validation, events, permissions, request context, migrations |
| `@blixis/kernel` | 🚧 in development | [`defineModule`](/api/kernel/functions/definemodule/) ✅; `createBlixis` and the runtime that loads your module are coming soon |
| `@blixis/testing` | 🚧 in development | `createTestBlixis` for module tests |

<Aside type="caution" title="Early development">
Blixis is not released yet. APIs marked *coming soon* in this manual do not exist yet; everything else is implemented and tested. The [API reference](/api/contracts/readme/) is generated from the source code on every build.
</Aside>

## Principles you will see everywhere

- **Explicit composition.** Modules are imported and listed in the app's config — no auto-discovery.
- **Typed end to end.** TypeScript 7, strict mode; configuration and inputs are validated with schemas.
- **Transport-agnostic services.** REST routes and GraphQL resolvers are thin; business logic lives in services.
- **Cloudflare-first.** Postgres (Neon via Hyperdrive) is the source of truth; Queues, KV, R2, and Workflows provide infrastructure. Modules never touch Cloudflare bindings directly.

The full rationale is in the [architecture document](https://github.com/blixis-io/monorepo/blob/main/docs/BLIXIS_ARCHITECTURE.md).
