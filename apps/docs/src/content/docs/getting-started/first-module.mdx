This walkthrough is a quick tour of `@acme/blixis-seo`, a module that stores SEO titles for content entries. It touches every part of the module contract in a few steps.

<Aside type="tip">
For the complete version, with storage, authorization, batching, and tests, read [Writing a module](/extending/authoring-guide/). It follows a working example that CI installs from packed tarballs and tests.
</Aside>

## 1. Create the package

```json title="package.json"
{
  "name": "@acme/blixis-seo",
  "version": "1.0.0",
  "type": "module",
  "exports": { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } },
  "peerDependencies": {
    "@blixis/content-api": "^1.0.0",
    "@blixis/contracts": "^1.0.0",
    "@blixis/kernel": "^1.0.0",
    "hono": "^4.13.0"
  },
  "dependencies": {
    "zod": "^4.6.0"
  }
}
```

Blixis packages and `hono` are **peer dependencies**: the Blixis app provides exactly one copy of each. `@blixis/content-api` is the content module's public API: its services and events. Use any [Standard Schema](/concepts/validation/) library; Blixis itself uses Zod.

## 2. Write the module

<Steps>

1. **Define a service and its token.** Other modules find your service through the token, never through your internals.

   ```ts title="src/service.ts"
   import { createServiceToken } from '@blixis/contracts'

   export interface SeoService {
     titleFor(entryId: string): Promise<string>
   }

   export const SEO_SERVICE = createServiceToken<SeoService>('@acme/blixis-seo.service')
   ```

2. **Add REST routes.** Routes use `ModuleHonoEnv`, which gives you the request context and services on `c.var`.

   ```ts title="src/routes.ts"
   import type { ModuleHonoEnv } from '@blixis/contracts'
   import { Hono } from 'hono'
   import { SEO_SERVICE } from './service.ts'

   export const routes = new Hono<ModuleHonoEnv>().get('/entries/:id', async (c) => {
     const seo = c.var.services.get(SEO_SERVICE)
     c.var.requestContext.logger.info('seo lookup', { entryId: c.req.param('id') })
     return c.json({ title: await seo.titleFor(c.req.param('id')) })
   })
   ```

3. **Handle an event.** Keep handlers idempotent — events can be delivered more than once.

   ```ts title="src/events.ts"
   import { entryPublished } from '@blixis/content-api'
   import { subscribe } from '@blixis/contracts'

   export const refreshSeo = subscribe(entryPublished, 'refresh-seo', async (envelope, ctx) => {
     ctx.logger.info('refreshing seo', { entryId: envelope.payload.entryId })
   })
   ```

4. **Put it together with a factory.** The factory takes typed options; the kernel validates them with `configSchema` and hands the result to `setup` as `ctx.config`.

   ```ts title="src/index.ts"
   import { defineMigration, definePermission } from '@blixis/contracts'
   import { defineModule } from '@blixis/kernel'
   import { z } from 'zod'
   import { refreshSeo } from './events.ts'
   import { routes } from './routes.ts'
   import { SEO_SERVICE } from './service.ts'

   const SeoConfig = z.object({ defaultTitle: z.string().default('Untitled') })

   const seo = defineModule<{ defaultTitle?: string }, z.infer<typeof SeoConfig>>((options = {}) => ({
     meta: {
       name: '@acme/blixis-seo',
       version: '1.0.0',
       requiresCapabilities: ['blixis.content'],
       capabilities: ['acme.seo'],
     },
     config: options,
     configSchema: SeoConfig,
     setup(ctx) {
       ctx.services.provide(SEO_SERVICE, { titleFor: async () => ctx.config.defaultTitle })
     },
     rest: { path: '/seo', app: routes },
     graphql: { typeDefs: 'extend type Sys { seoTitle: String }' },
     permissions: [
       definePermission({ id: 'seo.read', description: 'Read SEO metadata', defaultRoles: ['admin', 'editor', 'viewer'] }),
     ],
     events: [refreshSeo],
     migrations: [
       defineMigration({ id: '0001_create_seo', up: 'create schema acme_seo; create table acme_seo.entries (entry_id uuid primary key, title text)' }),
     ],
   }))

   export default seo
   export { SEO_SERVICE, type SeoService } from './service.ts'
   ```

</Steps>

## 3. Register it in an app

```ts title="apps/api/src/blixis.config.ts"
import { contentModule } from '@blixis/content'
import seo from '@acme/blixis-seo'

export const modules = [/* database, users, spaces, permissions, … */ contentModule(), seo({ defaultTitle: 'My site' })]
```

Modules are registered **explicitly** — Blixis never scans `node_modules`. At startup the kernel checks that `blixis.content` is provided, validates your config, runs `setup`, and mounts your routes at `/api/v1/seo`.

## 4. Test it

```ts title="test/seo.test.ts"
import { asUser, createTestBlixis } from '@blixis/testing'

const t = await createTestBlixis({ modules: [...firstParty(), seo({ defaultTitle: 'Home' })], database: db })
const res = await t.request('/api/v1/seo/entries/42', { actor: asUser(ownerId) })
```

`firstParty()` lists the modules you depend on (database, users, spaces, permissions, content); see [Writing a module](/extending/authoring-guide/#9-test-it) and [Testing modules](/concepts/testing/).
