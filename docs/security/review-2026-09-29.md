# Security review — 2026-09-29

Roadmap task [020.004](../plans/020-observability-and-security-hardening/004-security-review.md). Scope: the API Worker (`apps/api`) with every first-party module, the kernel and platform packages, CI, and the staging deployment at `main` after #154. The admin SPA was reviewed only where it touches the API (CORS, cookies). A full code review of the same revision is in [`docs/CODE_REVIEW.md`](../CODE_REVIEW.md).

Method: code reading per area, the existing security test suites, probes against staging (`blixis-api-staging.frosty-hill-6079.workers.dev`), `pnpm audit`, and a licence inventory. Not done: penetration test, fuzzing, review of Cloudflare account settings.

Severity: **high** blocks plan 020 and launch; **medium** is fixed in this task; **low** is fixed or accepted with a reason.

## Findings

| # | Severity | Area | Finding | Status |
|---|---|---|---|---|
| 1 | high | Abuse protection | API rate limiting does not enforce on staging: the Workers Rate Limiting binding answers `success` to every call (020.003). Only the sign-in throttle is effective. | **Open, blocking.** WAF rate limiting rules required before launch (022.005); promotion gate in 021.001. |
| 2 | medium | Headers | API responses had no security headers (`nosniff`, `Referrer-Policy`, HSTS, frame denial, CSP). | **Fixed:** kernel sets them on every response unless the handler set its own. |
| 3 | medium | Input limits | REST JSON bodies had no size limit; one request could make the isolate parse up to the platform's request limit. | **Fixed:** JSON bodies capped at 1 MiB (`createBlixis({ maxJsonBodyBytes })`), also without `Content-Length`; `400 VALIDATION_FAILED`. |
| 4 | low | Supply chain | No automated dependency audit or licence check. | **Fixed:** CI `pnpm audit:check` (high and critical, production dependencies) and `pnpm licenses:check` (policy in `tooling/licenses`). |
| 5 | low | Supply chain | `undici` 7.28 (moderate, WebSocket decompression DoS, GHSA-3wwx-pv8p-q78v) via `@sentry/cloudflare` → `wrangler` → `miniflare`. | **Accepted:** development tooling pulled in through an optional peer; not in the Worker bundle. Disappears with the next Wrangler update. |
| 6 | low | GraphQL | GraphiQL is served on staging and local (never production) and loads its script from `unpkg.com` without integrity pinning, on the API origin. A token pasted into it is exposed to that script. | **Accepted:** not in production; staging holds no production data. Use Postman or the SDK with real tokens. |
| 7 | low | Uploads | SVG and other images are served inline. | **Accepted (ADR 0013):** every delivered file gets `nosniff` and `default-src 'none'; sandbox`, so scripts in an SVG don't run and the document has an opaque origin. |
| 8 | info | CORS | Browsers can call the API only from `AUTH_ALLOWED_ORIGINS`; websites can't query the Delivery API from the browser. | By design for now (delivery keys are server-side secrets). Revisit with public delivery keys. |
| 9 | info | Transport | HSTS is only meaningful on the custom domain (`.dev` is already HSTS-preloaded). | Re-check on the custom domain (022.005). |

## Areas reviewed

**Authentication (plan 007).** Ed25519 access tokens (15 min), rotating refresh-token families with reuse detection, scrypt password hashes, generic credential errors, Postgres sign-in throttle per email and IP. Public sign-up is off by default (`authModule({ allowSignUp })`) and off in `apps/api`. API tokens (`blx_pat_`) are stored hashed, shown once, scoped, and can't exceed the owner's permissions. No finding.

**Authorization and tenancy (plans 008, 009).** Every tenant-scoped route is in both the isolation suite (`tooling/tenant-isolation/test/routes.ts`) and the authorization matrix (`authz-routes.ts`); both suites fail when a registered tenant route is missing (`uncoveredTenantRoutes`). The remaining global routes were checked by hand: `users/me*` (own user only), `permissions` and `field-types` (require a signed-in actor), `organizations` list and create (own memberships; API tokens can't create organizations), `auth/*` (own tokens and session), and the public `health`, `jwks`, and `openapi.json`. No finding.

**Cookies.** The refresh cookie is `HttpOnly; Secure; SameSite=Strict`, scoped to the auth path, and cookie-based refresh and sign-out require an allowed `Origin` (CSRF). No finding.

**CORS.** Exact origins from `AUTH_ALLOWED_ORIGINS`; credentialed only for those; `Vary: Origin`; preflights from other origins get no CORS headers. See finding 8.

**SSRF (webhooks, plan 015).** `https:` only in deployed environments, public host names and IPs only (private, loopback, link-local, CGNAT, documentation, multicast, IPv4-mapped and NAT64 IPv6 blocked), checked on save and before every delivery, `redirect: 'manual'`, 10 s timeout, response excerpt capped at 1 KiB. DNS rebinding to private addresses is not checked in code; Workers can't reach private networks. No finding.

**Uploads and delivery (plan 014).** Size limits per upload and multipart part, content type recorded not trusted, storage keys never built from file names, delivery with `nosniff`, sandboxing CSP, `attachment` for everything that isn't an image, audio, video, or PDF. See finding 7.

**GraphQL (plans 012, 013).** Depth 12, aliases 30, tokens 3000, cost 20 000, body 64 KiB, list sizes capped; introspection limited to members in production; Yoga error masking on, public errors mapped explicitly; GraphiQL off in production. See finding 6.

**Error leakage.** Unexpected errors become `500` problem responses without messages, hosts, or stacks; readiness answers `503` without details. No finding.

**Logging and error reporting (020.001, 004.007).** Secrets redacted by field name and by shape, stacks only at debug level, URLs logged as route patterns; Sentry without bodies, cookies, user data, or credential headers. No finding.

**Secrets.** Inventory in [Cloudflare → Secrets](../operations/cloudflare.md#secrets) and [configuration](../operations/configuration.md): `AUTH_SIGNING_KEYS`, `WEBHOOK_SECRET_KEYS` as Worker secrets per environment with rotation procedures; database credentials only inside Hyperdrive (application role, no DDL); CI secrets per GitHub environment, none available to pull requests; npm publishing by OIDC trusted publishing (no token). `wrangler.jsonc` holds only non-secret values (the Sentry DSN is public by design). No finding.

**Dependencies and licences.** 445 production packages: MIT, Apache-2.0, ISC, BSD, BlueOak, CC0, 0BSD, Unlicense, Python-2.0, and one MPL-2.0 build tool (`lightningcss`, exception recorded). See findings 4 and 5.

**Headers and input limits.** See findings 2 and 3.
